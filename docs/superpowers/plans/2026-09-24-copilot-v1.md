# 对话副驾 1.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付可本机运行、可退出、默认不抢焦点的 Windows 对话副驾候选，通过验证后发布 1.0。

**Architecture:** Electron 只控制自己的窗口，Python Win32 helper 仅输送几何状态；独立同源副驾页调用默认关闭、按次授权的回复服务。源码工作与私有部署分离，合成测试不连接真实聊天。

**Tech Stack:** 已有 Python 3.12/标准库、Node 24、精确锁定 Electron 44.4.5、HTML/CSS/原生 JS、Node test / unittest。

---

常规设计/执行方式由已记录的项目托管授权审定；用户已批准视觉方向和本轮原生行为，不重复要求技术选型确认。源码在干净公开仓库的新 `codex/copilot-v1` 分支，私人运行目录不作开发仓库。

## Task 1: 回复服务与准入

**Files:** `dashboard/copilot/{__init__,context,contract,service}.py`，`dashboard/analysis.py`，`dashboard/modules.py`，`dashboard/app.py`，`tests/test_copilot_service.py`，`tests/test_copilot_api.py`，`tests/test_module_policy.py`。

- [ ] 写失败合成测试：模块默认 False；preview 不调用 provider；字面 consent=True 才消费；相同 preview 只消费一次；所有范围与配置变更拒绝旧 preview；无其他会话；错误无原话。
- [ ] 运行 `python -m unittest tests.test_copilot_service tests.test_copilot_api tests.test_module_policy`，先观察缺少新模块/行为导致的失败。
- [ ] 独立 JSON transport 保留旧报告入口：`_request_result(config,key,content,system)` 继续调用 `_safe_result(_request_json(...), context=content)`。回复使用 `_request_json` 和自己的固定契约，不调用旧 timeline 校验。
- [ ] 建立如下接口（所有写入口保持原 Host/Origin/session）：

```text
GET  /api/copilot/status
POST /api/copilot/preview
  {bundle_id,date_from,date_to,max_messages,direction,latest_draft,binding_revision}
POST /api/copilot/run
  {preview_id,consent:true,binding_revision}
```

`max_messages` 默认 80、范围 1..200，draft 最大 4000，revision 非负整数；direction 固定 `closer|relaxed|invite`。preview 返回 counts/provider/model/范围/one-use ID，不返回历史原话；run 返回结果或固定错误且不自动 retry。预览内存上限 64、有效期 600 秒，consume-before-send，进程重启不复活授权。

```json
{"replies":[{"style":"natural","text":"合成建议","reason":"接住当前话题"},{"style":"warm","text":"合成建议","reason":"轻松表达"},{"style":"invite","text":"合成建议","reason":"留有选择"}],"topics":[{"title":"共同兴趣","text":"合成话头"}],"caveats":["不代表对方意愿"]}
```

- [ ] 跑新测试和 `test_scoped_analysis`/`test_analysis_response_diagnostics`，review 安全边界后提交精确文件。

## Task 2: Win32 只读状态输入

**Files:** `scripts/copilot_window_watch.py`，`tests/test_copilot_window_watch.py`。

- [ ] 先测协议字段/类型、窗口过滤、零/多候选、HWND/PID复用、不可见/最小化、输出无标题或路径。
- [ ] 测试失败后实现标准库 ctypes 包装，封装枚举、几何、前台与消息循环，低频校准且仅输出变更或心跳。只允许 Weixin/WeChat 顶层普通窗口，零/多候选 fail closed。

```json
{"version":1,"state":"bound","target":"opaque-generation","rect":{"x":100,"y":80,"width":800,"height":700},"visible":true,"minimized":false,"foreground":true}
```

错误固定 `WINDOW_UNAVAILABLE|WINDOW_AMBIGUOUS|UNSUPPORTED_PLATFORM`。helper stdout 只放协议，stderr 不打印异常对象；父进程退出/管道关闭即结束。

- [ ] Python unit 验证；只读实机诊断仅输出候选数量和状态，不打印窗口标题/路径。

## Task 3: 桌面壳与纯定位策略

**Files:** `desktop/copilot/{package.json,package-lock.json,main.cjs,preload.cjs,placement.cjs,window-controller.cjs}`，`desktop/copilot/tests/*.test.cjs`，`start_copilot.ps1`。

- [ ] 先写纯函数 `placePanel({target,workArea,size,mode,gap})` 的左右/窄屏/负坐标/浮动 clamp 用例；先失败后实现。
- [ ] 状态机事件 `update(snapshot)` 仅在唯一目标可见、非最小化、前台为目标或副驾且未暂停时 showInactive；其他 hide。相同 bounds 不更新；2 秒未收到 helper 状态隐藏。窗口 identity 变化发 binding-change 让页面清上下文。
- [ ] Electron 加载精确 `http://127.0.0.1:<port>/copilot/index.html`，端口仅整数1024..65535，nodeIntegration=false/contextIsolation=true/sandbox=true。preload 只暴露 `setMode`, `setSize`, `pause`, `close`, `onState`，验证发送方frame/url/参数；不提供任意 execute/read/request。
- [ ] 使用固定 Python executable 与 helper 路径，不运行任意渲染器命令；只作用自有进程。单实例锁、关闭退出、tray 明确退出；没有开机启动或自动安装。
- [ ] `npm ci --ignore-scripts` 后显式运行官方 Electron 安装脚本；生成 lockfile，下载只来自官方 npm/GitHub，不接受未核验镜像。
- [ ] `node --test desktop/copilot/tests/*.test.cjs`；原生合成 target 验证不抢焦点/最小化/恢复。预先定义目标测试不操作真实微信。

## Task 4: 实用副驾界面

**Files:** `dashboard/static/copilot/{index.html,copilot.css,copilot.js}`，`tests/test_copilot_ui.py`。

- [ ] 先写浏览器合成用例：缺模块/未配置、会话选择、变化清空、preview→明确confirm→run、双击单次、晚到结果拒绝、XSS、无自动请求。
- [ ] 以获批绿白样机为视觉依据实现独立页面，不复制模拟文案到真实建议。模块未启用明确按钮且点击才启用，选会话后显示归档时点、方向、日期范围、最新文字输入。
- [ ] 回应分“怎么回复/接着聊什么/同城灵感”；未接外部来源明确提示，不伪造。复制只发生于用户点击；不读剪贴板，不自动粘贴微信。
- [ ] 默认紧凑/胶囊，配置折叠；原生事件仅更新状态/清理绑定，不在页面失焦时抢焦点。不播放声音，不弹系统通知。
- [ ] 跑合成 browser tests、JS 语法、窄屏和长内容；使用页面截图做视觉审查，不打开真实聊天截图。

## Task 5: 集成、审查、发布候选

**Files:** `README.md`、`BACKLOG.md`、`CHANGELOG.md`、`docs/copilot.md`、`docs/reviews/v1.0.0-rc.1-review.md`、`VERSION`（明确标记候选；正式验收后才移除 `rc`）。

- [ ] 全量 `python -m unittest discover -s tests -p 'test_*.py'`，显式记录环境条件跳过；Node tests、新浏览器测试、原生合成测试分别记录。
- [ ] 独立 spec review，然后 code/security review，修复后复跑。
- [ ] 仅白名单部署新增壳和必要源文件到私人运行区，先核对现有服务状态；不覆盖聊天/配置/备份，不自动重启在途服务，不自动请求模型。
- [ ] 核验启动器可重入/退出、窗口只读绑定状态，不能把“进程启动”当功能全部完成。
- [ ] 准备公开提交前运行 `scripts/check_public_release.py`，核对精确 staged diff、匿名作者；创建 PR 后 attach artifact。正式版本必须当前 CI 与验收一致，缺门槛保持候选并诚实说明，不为满足版本名伪报上线。

计划自审：窗口/native、服务、安全、UI、发布分别可测试；真实消息自动识别没有可用契约，明确不作为已实现能力；所有云调用必须经新的单次 preview，托管授权不扩大此边界。

实施记录：Task 1–4 的候选源码与定向合成验证完成；Task 5 进入整仓回归、部署与发布边界核验。整仓首轮出现既有备份终态读取竞态与旧 UI 用例等待竞态，纳入最小回归修复，不放宽断言或备份完整性。软件与桌面包暂同标 `1.0.0-rc.1`，不冒称正式 1.0；实测和最终结果以审查记录及当前 CI 为准。
