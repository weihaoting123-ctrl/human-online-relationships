# 聊天节律 / 热度视图

状态：受托范围已确认，源码实现及独立审查完成，发布以对应 Release 为准。基线 v0.1.2；常规设计由维护代理按项目托管规范决定。

## 选择

目标是在一个会话中看清“哪天、哪时消息多”，不读取正文做判断，不自动运行 AI。
比较年度点阵、月历与纯折线：年度点阵密集但手机难以点选；折线已有。
选用可展开的月历热度 + 星期/小时分布。月份是真实日历，每格保留日期及消息数；
密度色只作辅助。保留现有时间线及高频阶段，不另造情感分数。

入口在会话详情。首次展开才读取聚合接口。默认以最新有效归档日期为终点取 90 天；
显式注明不是“今天”。自定义起止日期含首末日，最多 366 天，超限拒绝而不是截断。
可重置默认范围；空档案以本机今天为终点并明确无消息。范围、联系人不写入 URL 或浏览器存储。

## 契约

`POST /api/activity/heatmap`，JSON 为 `bundle_id` 与可选的 `date_from/date_to`。
这是只读计算；POST 避免范围/身份出现在请求 URL。要求同源本机会话及可见档案；
两个日期同时提供或同时省略，拒绝未知参数。复用安全 `_source` 读取器的大小、路径及一致性检查。
响应 `{"status":"ok","heatmap": ...}`；错误固定中文，不反射参数、路径或正文。

聚合 `build_chat_heatmap(payload, scope, now=None)` 无 I/O、无云调用。
复用现有时间解析：本机时区，秒/毫秒/ISO，年份 2000–2100。
按顺序互斥排除无效、未来、系统消息；其他所有消息类型计数，不按正文或时间去重。
只读时间戳及 type，不读内容/转写/名字/媒体路径。线性扫描，输出最多 366 日 + 168 时段。

固定输出字段：

```text
version: 1, as_of: ISO, timezone: "server_local"
available_range: {date_from: str|null, date_to: str|null}
scope: {date_from, date_to, days}
days: [{date, count}]  # 连续，包含零；升序
weekday_hour: [[count]*24]*7  # 周一索引 0
summary: {message_count, active_days, daily_average, peak_day: {date,count}|null}
top_days: [{date,count}]  # 最多7个正数日，数量降序，同数日期升序
excluded: {invalid_timestamp, future_timestamp, system_messages} # 全档案
```

默认范围底线 2000-01-01；显式范围同样限制到 2000–2100。
超过真实今天的格子不得显示成已发生但零消息，界面注明未来日期不计消息。
未知发送方不用猜身份。统计量不是来回次数或聊天时长。

## 视觉与交互

复用系统标题/正文字体，数字等宽；不下载字体、图片或图表依赖。
底色 #f5f5f7、面板 #ffffff、正文 #1d1d1f，热度从 #e8f3f2 到 #197c78，强调 #0066cc；
深色从共享 token 取色。视觉重点是月历的青绿色密度，不增加无意义装饰。
日格不是按钮，准确数值直接可见；星期/小时表支持容器内滚动及表头，原生 details 支持键盘。
日期控件及按钮至少 44px；布局 320/390/768/1440px、深色、文字放大、减少动态效果可用。
在读、失败、空范围分开显示；修改日期立即清空旧结果并提示应用。
换人、收起详情、重置范围或新请求均作废旧响应；不持久化热度副本。

## 验收及非目标

敏感字段不出现在 DTO、鉴权/隐藏、文件不变、乱序响应、键盘/小屏/错误恢复。
所有夹具完全合成。完整回归及独立 review 后才发布版本。
不改导出/备份、数据库、AI 授权或旧报告；不跨会话合并；不自动升级私人运行实例。
