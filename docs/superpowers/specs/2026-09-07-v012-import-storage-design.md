# v0.1.2 离线导入保存安全设计

依据托管规范由代理确认本轮范围：DATA-01 第一阶段。当前应用 v0.1.1，公开基线 `db13580`；本地托管文档 `67bbaaa` 随本轮发布。所有开发和验收使用合成资料。

## 目标与方案选择

现有网页导入有暂存和新包语义，四个离线转换入口的默认保存行为尚不一致。候选方案：

1. 仅在目标存在时拒绝：改动小，但重复导入不能方便复用。
2. 共同的不可覆盖保存层：完整暂存后发布新包，同一材料核验后复用；保留现有数据格式与路径定位函数。选择此方案。
3. 改为统一数据库内容仓储：影响迁移、媒体与备份，超出本轮，暂不采用。

成功标准：重复执行不会修改已有归档；不同材料不会覆盖旧包；消息与表情目录一起发布；并发、中断和损坏状态不会被报告为成功复用。

## 有界范围

- 接入 `convert_markdown.py`、`convert_weflow.py`、`convert_weflow_cli.py`、`convert_ciphertalk.py` 的默认联系人包保存，保留 CLI 参数和原有成功字段，增加 `created/reused` 结果。
- 网页保持现有原始文件、统计与响应 DTO 流程；共用根导入锁，并修复复用身份和内容核验，不把 CLI 与网页结果无条件跨入口复用。
- 不改变 `contact_bundle.resolve_bundle_paths`、已有包 ID、消息归一化/排序、管理库、显式 `merge_into_bundle` 或自动同步检查点。
- 旧微信/QQ 在线兼容提取器、显式 `--output` 文件模式、导入预检向导、原生采集和完整 SRC-01 收敛仍为后续工作。不因此关闭主需求 #15，也不宣称 DATA-01 已全部完成。

## 保存层契约

新增 `scripts/import_store.py`，职责是保存而非解析或合并：

```python
fingerprint_import(payload, *, identity_context, sidecars=None) -> str
exclusive_import_lock(contacts_dir)  # context manager, non-blocking OS lock
save_import_bundle(payload, *, contact, contact_id, output_dir,
                   identity_context, sidecars=None) -> dict
# result: payload, bundle (existing path keys), created, reused
```

- 接收适配器已经准备的对象，不再次 normalize、drop 或 dedupe；真实重复消息及原始 dropped 统计保留。拒绝空消息包或不可序列化材料，使用固定错误码，不回显输入。
- 指纹覆盖转换结果、明确来源/联系人/账号/转换选项和附带 JSON；分别排除消息对象与每个 sidecar 的顶层保存位置 `bundle_dir`。不把源文件路径或文件名作为身份，不按同名猜测同一个人。身份上下文分别记录请求参数与载荷原值：Markdown 的 contact/contact_id/my_name，WeFlow 的 display_name/wxid/own_wxid，WeFlow CLI 的 contact/contact_id/own_wxid，以及 CipherTalk 的 contact/contact_id 和转换前原始 `meta.ownerId`；网页还记录实际格式与载荷原联系人/账号字段。WeFlow 两种入口共同保留所有明确 outgoing 消息里的可用发送方标识，不据此猜选唯一账号。
- `sidecars` 本轮只允许 `emojis.json`，和消息一起封存；保存层在副本中填入最终 `bundle_dir`，不修改调用者的对象。
- 首次可沿用既有定位函数给出的目录名；该路径已被占用时只能另选新目录，不覆盖、补写或删除原目录。不要修改全局路径函数来改变同步定位。
- 保存清单 `import_manifest.json` 使用独立版本，包含输入指纹及 `messages.json`/附带文件的完整摘要。只有清单版本、身份指纹、完整预期文件集合和每个材料的摘要均匹配才复用，返回原路径且不更新文件时间。返回的全部 bundle 路径字段以最终目录重建。
- 无清单的旧包、摘要不符、缺失 sidecar 或损坏材料原样保留，不修补或冒充复用；新导入可生成新包。旧包不迁移、不重写。
- 暂存目录放在 contacts 的同文件系统私有兄弟区域，不出现在目录发现范围。全部材料写入、flush/fsync 和清单完成后，在锁内一次发布完整目录；异常只清理本次创建的暂存物，不删除任何既有目录。崩溃留下的未提交暂存物不作为有效归档，也不自动清理未知目录。
- 根目录与内部工作路径拒绝符号链接/reparse 重定向；候选查找不跟随目录或材料链接。允许范围只有选定输出根及其经验证的固定私有兄弟区域；创建/打开前检查祖先、锁文件和暂存根，不允许 sidecar 路径穿越。
- Windows/POSIX 使用系统拥有的非阻塞锁，共用原网页 `contacts.parent/private/dashboard-import.lock`。跨进程竞争者得到稳定忙碌错误，不自动重试；网页同进程线程仍由原有 RLock 串行，保留两个请求成功复用的兼容行为。进程结束后 OS 锁自然释放。
- 发布前在共享锁内重新检查占用，普通文件、空目录、断链也算已占用；保护范围为遵循共同锁的写入者，不保证阻止旧提取器或其他程序的非协作竞争。目录 rename 成功即提交，之后返回失败不得删除已发布包；重试应复用。POSIX 对目录做可用的 fsync，Windows 仅承诺系统可用的文件 flush/fsync 与目录发布，不把进程退出测试当作断电持久性证明。

## 网页复用修复

- 新指纹包含请求的来源、明确联系人标识、载荷中的联系人/账号、双方显示名及实际转换结果。仅内容相同不能跨已知身份复用。
- 新网页清单记录指纹版本、身份上下文、消息文件摘要；命中时重新验证当前材料，不因清单残留而返回已被修改或损坏的包。
- 旧 v1 网页指纹缺少完整身份，不猜测升级为 v2；旧档案保留可读，首次重新导入可能产生一个新包。之后同一 v2 请求保持幂等。公开说明此兼容取舍。
- 共用根锁时保留 `_IMPORT_LOCK` 和 `_exclusive_import_lock()` 兼容入口；拒绝写入、原始归档回滚、隐藏会话处理及同源安全保持原行为。
- 网页暂存也移至固定私有兄弟区域；复用扫描排除点目录、链接及历史未提交暂存，不能把写完清单但尚未发布的暂存包复用。

## 错误与交互

四个离线转换 CLI 的异常出口改为固定错误码和稳定说明，缺文件/解析失败/保存忙碌/本机 I/O 不输出原文、路径或 traceback。输出路径只保留在本机成功结果中。网页仍由已有 HTTP 安全错误层处理，不新增云调用、联网下载、自动重试或 UI 功能。

## 验收与发布

1. 四 CLI 的 A→A、A→B、同材料不同来源路径；消息/表情/已有分析文件字节及 mtime 核对。同时间同内容不同 ID、完全相同重复记录均保持，含无效项时原有 dropped 统计不因二次归一化被重置。
2. 保存层来源/联系人/账号/选项隔离，损坏清单/文件/sidecar、空包、链接与路径边界，调用者对象不变。
3. 暂存消息、sidecar、清单、发布及发布后返回阶段分别注入失败；只有完整包可被发现，已提交包不回滚删除。两个进程的竞争拒绝和退出释放锁可复验。
4. 网页身份隔离、内容损坏不复用、旧清单保护、同输入幂等和现有导入/失败回滚/响应隐私回归。
5. 独立规范和质量审查，全部现有合成 Python/浏览器与 Node 测试及公开扫描。本机验收后更新 VERSION/CHANGELOG，再要求同一最终候选提交通过 Windows/Linux CI，才合并发布 v0.1.2；不重写 v0.1.1。

独立设计审查指出的身份、暂存发现、sidecar 集合、提交点、路径范围和线程兼容问题已纳入上述约束。工作区为与私人部署隔离的公开源码普通 checkout，使用专用 `codex/` 分支；不是 Git linked worktree，也不需要再次复制运行区。

不读取真实账号、聊天、媒体或密钥，不运行私人部署，不以合成验证冒充真实采集或灾难恢复验收。
