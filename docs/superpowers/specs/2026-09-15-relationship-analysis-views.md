# AI-05：关系分析视角

## 决策与范围

维护者认为旧的「本次关注」与「人类线上关系可视化」主题不符。依照项目托管规范，由代理选择以下有界方案，无需再次要求维护者完成日常设计选择。沿用 D 盘公开源码工作区和独立功能分支，私人运行部署另行验证；不新增工作树或安装依赖。

表单改为「分析视角」，默认「关系全景」，使用现有系统原生选择器及一行随选项变化的说明，不增加卡片、弹窗或新的视觉框架。

| ID | 名称 | 关注范围 |
| --- | --- | --- |
| relation_overview | 关系全景 | 阶段、关键事项与变化，适用朋友、家人、同事等关系 |
| interaction_rhythm | 互动节奏 | 可观察的联系节奏、参与与变化，不以频率衡量感情 |
| key_moments | 关键节点 | 有证据的讨论、转折与阶段，不强行制造事件 |
| shared_plans | 共同计划 | 提出、推进、明确报告的结果，以及没有后续证据的计划 |
| contact_gaps | 联系空白 | 所选归档内的空白、恢复联系及明确提及的背景 |
| communication_boundaries | 沟通与边界 | 明确表达的需要、分歧、边界与可选沟通建议 |

## 契约与兼容

- `dashboard/static/analysis-focus.json` 是唯一可信视角目录；Python 和页面读取同一份目录。字段为 `version / default / presets`，每项为 `id / label / description / guidance / legacy`。
- 六个新视角有内置 guidance；仅从本地代码目录读取，不能由请求覆盖。分段和汇总均将它追加到系统提示，保持原有 JSON、证据、不推断心理和不操纵的约束优先。
- 四个旧 ID 继续被后端接受，原标签不改，guidance 为空，原模型提示及缓存语义保持不变。新表单不列出旧选项；重新核对旧部分报告时临时加入其原选项，并注明旧版视角，不暗中换方向。
- 提示版本散列实际使用的两个系统提示：新视角 guidance 的变化作废该视角的预览及缓存；文案或其他视角变化不会无故作废无关缓存。调用预算包含新增提示。
- 切换视角清空预览及发送/重复计费确认。目录加载失败时禁止新预览；不妨碍读取历史或配置，错误文案固定，不回显响应内容。未知历史视角不自动转换为默认方向。

## 非目标与安全

不重新分析，不发送聊天，不访问真实归档、媒体或密钥，不修改源微信记录，不改定时任务、模型配置或输出 schema。不新增关系评分、人格标签、读心结论或操纵建议。日期级样本不能推导精确回复速度；归档空白不等于现实失联，历史区间不能解释当前未联系原因。
