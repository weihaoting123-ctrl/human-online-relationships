# v0.1.1：首次导入与导航修复设计

依据已提交的需求池 R1 中 UX-01 至 UX-05。用户在确认首轮方向后补充要求：完成后自行进行完整 review 和 debug。本规范细化同一范围，不扩大到 v0.2.0 工作台重构。

## 目标与非目标

让“选文件 → 本机导入 → 核对结果 → 查看会话 → 返回清单”形成可预测的流程。版本继续采用原生 JavaScript、HTML/CSS、Python HTTP 服务与已有 SQLite，不新增依赖。

不改变导入端点、格式、50 MB 限制、数据包身份、去重或保存策略；不实现新的导入预检/提取/账号选择；不改变模型、授权、缓存、备份或数据库 schema；不连接真实微信，不运行付费调用。

## 行为设计

### 1. 文件来源

- 文件选择与拖放使用同一处理函数。
- 来源选择属于当前文件。每次选择一个新文件，`.md`/`.txt` 自动选 Markdown，其他扩展名选 JSON 自动识别；这会清除上一个文件的手动来源。
- 用户可在选定当前文件后手动覆盖来源。提交前不再根据扩展名改回，失败保留该文件和手动选择。
- 清空选择回到默认状态。正在提交时固定使用提交时的文件、来源和称呼；不得因用户切换输入而把返回结果误归到新输入。

### 2. 导入结果与异步边界

- 提交期间按钮忙碌且禁止重复提交；将原始输入快照与当前用户导航/会话选择代次一起记录。
- 已确认成功先保留返回结果，再刷新资料库。刷新失败不能把已经成功的导入说成失败，也不得提示自动重传。
- 用户仍停留在原导入上下文时，展示该结果并进入目录详情；在等待中主动切换页面或选择另一会话时，不抢走其当前视图/焦点，提供明确“查看已导入会话”入口。
- 成功后的表单清理只作用于本次提交快照；不能清掉等待过程中刚选择的新文件或新输入。
- 网络中断、无效响应等导致写入结果无法确认时，保留输入并提示先刷新核对，绝不自动重试。

### 3. 空状态

- 初始加载、加载失败、确实零档案、已有档案但筛选无匹配是不同状态。
- 只有成功读取且归档总数为零，才显示首次导入引导；只有已有归档且当前筛选无结果，才显示无匹配提示。
- 首次导入入口直接转到维护页并展开导入表单，焦点落到文件选择控件。
- 读取失败保留最后一次成功数据（如有），显示失败通知，不以空数组覆盖为“暂无资料”。

### 4. 导航与焦点

- 用户主动切换视图写入新的历史条目；初始化、无效 hash 归一化用替换；浏览器前进/后退只恢复视图，不再追加历史。
- 保留旧 `#catalog`、`#analysis-workspace`、`#maintenance`、`#settings`、`#trash`；URL/history state 不存联系人、查询词、日期、文件或正文。
- 视图变化增加本机导航代次；异步结果据此决定是否允许自动跳转。
- 打开详情后焦点落到详情标题，关闭时重新查找同一会话的当前按钮；若已被筛掉/隐藏/移除，回到目录标题或搜索控件。
- 只在用户明确操作对应的结果完成时转移焦点；后台刷新与迟到响应不得抢焦点。减少动态效果时不使用平滑滚动。
- 可选 AI 脚本不存在或模块停用时，核心导航与历史仍能工作。

### 5. 请求错误

- 共享请求层区分网络不可达、主动取消/超时、无法读取响应、非对象 JSON、有效服务端拒绝。
- 技术异常对象与响应原文不直接展示；保留受保护本机接口明确返回的可理解业务拒绝信息及 HTTP 状态（尤其 409 冲突）。
- 保留 AbortError 名称/取消语义，使已有搜索取消逻辑不被误报为失败。
- 结果未知的写请求提示核对再决定重试；任何分支都不自动重传。不新增全局超时或网络重试策略。
- AI 独立授权、未知计费提示、额外重试确认维持原样。

## 文件与责任

| 文件 | 本轮职责 |
| --- | --- |
| `dashboard/static/app.js` | 文件状态、导入结果、目录空态与详情焦点 |
| `dashboard/static/core.js` | 共享请求错误、必要的本机状态字段与滚动辅助 |
| `dashboard/static/shell.js` | 导航历史、导航代次、视图聚焦与首次导入跳转 |
| `dashboard/static/index.html` | 导入结果可达入口、首次导入链接、可聚焦标题/状态语义 |
| `dashboard/static/apple-ui.css` | 仅当新状态/入口需布局时复用已有主题，不重新换肤 |
| `tests/test_import_navigation_ui.py` | 全合成浏览器回归，复用现有随机端口夹具 |
| `tests/test_dashboard_ui.py` | 必要时补真实本机端点的合成导入整合验证 |
| `VERSION`、`CHANGELOG.md`、`BACKLOG.md`、`docs/release-verification.md` | 验收后记录实际版本和证据，不提前勾选完成 |

若拆出小型导入模块确有必要，应保持旧入口的薄适配层并补脚本缺失测试；不得为修复顺手重排整个前端。

## 完整 review / debug 验收

1. 先新增回归并观察原代码按预期失败，再实现修复。UI mock 只替换外部响应，不替换待测 DOM 或业务函数。
2. 覆盖选择/拖放双向切换、手动来源、重复点击、导入确认成功但刷新失败、迟到结果、输入中途改变、零资料/无匹配/加载失败、前进后退、详情焦点、断网/取消/无效响应/409。
3. 使用现有浏览器夹具检查浅深色、320/390px、键盘、减少动态效果、恶意显示名、没有可选 AI 脚本、授权默认不勾选；不截图真实控制台。
4. 独立审查分两步：逐项核对本规范，再检查边界、时序与测试质量。主代理复核报告，不以代理的“通过”代替证据。
5. 完整运行 Python 合成回归、Node 目录测试、JavaScript 语法检查、文档/差异检查与公开发布扫描；失败逐项找根因、修复、重跑相关和完整测试。
6. 再核对 GitHub CI 和同一提交，才允许发布 `v0.1.1`。不重写旧标签，不把未完成 B–D 批次记为完成。
7. 完整 review 指关键模块与全部现有合成回归覆盖，不宣称形式化验证、渗透测试或全部平台实机验收。现存独立安全债务在本机审查并说明发布影响，未验证事项如实保留。

## 失败与回退

补丁不改变持久数据格式。回退只切换已验证源码版本，不删除管理库、已导入消息、转写、报告或备份。不停止正在处理的私人分析或备份，不将公开源码发布自动等同私人部署升级。

## review 中的有界补充

- `library-ui.js` 移除一处重复空态覆盖，由目录渲染负责加载/失败/零档案判定；元数据写入使在途目录请求失效时，同步结束其加载状态，未完成首次读取仍保持未知并可刷新恢复。
- `analysis-ui.js` 消费本次授权时清空重试勾选；本次请求仍使用此前捕获的授权，不改变模型或调用策略。
- 目录重绘只保留重绘前当前行的键盘焦点，并重新按身份定位；不聚焦已消失的行，不覆盖搜索或设置控件焦点。
- 在既有 AI/备份浏览器测试中补响应丢失回归；在真实导入端点夹具中验证结果与幂等复用；修正 Apple 主题测试的旧节点测量时序。
- 上述均是本轮交互与共享请求改动的回归保护；没有扩展到后端提取、持久格式或新的模块功能。
