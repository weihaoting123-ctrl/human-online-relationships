# 对话副驾 1.0：低打扰桌面伴随

状态：设计已审定，实施中，尚未发布。用户已批准可交互方案，并指定正式桌面版、悬浮/磁吸、跟随移动/缩放/最小化，以及尽量无感。常规技术审定按 `docs/project-stewardship.md` 委托执行；不代替真实数据外发确认。

## 目标与范围

为 Windows 本机控制台增加独立桌面副驾。优先完成一个真正可运行、可退出、可验证的窗口伴随与回复工作流，不把网页中的模拟悬浮称为原生悬浮。

- 原生独立窗口：自由悬浮、自动吸附、展开/紧凑/胶囊三种状态。
- 吸附随绑定微信窗口移动、调整大小；最小化/隐藏/退出则一起隐藏，恢复不抢焦点。
- 非微信/副驾前台时隐藏；用户主动点开设置才允许正常交互焦点。不弹 toast 通知到桌面、不播放声音、不自动展开候选。
- 单会话归档历史、用户主动输入的新消息、关系方向，形成一份短期本机预览；明确确认一次才向已配置服务商发出一次请求。结果是可复制的回复/话题，不发送微信消息。
- 单独显示归档时点。窗口跟随不等于已识别联系人或读取实时消息。未经实机验证的自动识别能力显示未接入，绝不静默按窗口标题猜人或将归档轮询标为实时。
- 同城灵感先提供城市/兴趣及用户给出的公开活动信息作为手动话题入口，未接实时来源就显示未接入，不造小红书活动和来源。

自动 UIA/OCR 读取、持续无人确认云调用、跨会话身份推断、自动发送、账号切换、原库修改、开机自启、系统服务注册不在本版默认能力内。实时适配是独立接口与验收门槛；不得因此把未完成部分标成已支持。

## 技术选择

1. **Electron + Python 只读窗口助手（选用）**：复用已批准 Web UI 和现有同源 HTTP/凭据边界，无本机 Node addon 编译链。代价是桌面运行时体积和内存，需精确锁版本。
2. WPF + Win32：原生集成很好，但当前环境没有 .NET SDK，且要重写已批准界面、增加 HTTP 会话客户端。
3. 浏览器小窗：最轻，但无法可靠跟随其他应用窗口，不能满足本轮核心要求。

Electron 只负责自己的窗口；Python `ctypes` 只读取微信进程/窗口的几何、前台、可见性与最小化状态。禁止 SetParent、注入、读取内存、修改微信样式或控制微信。微信识别仅认固定进程名与顶层窗口，零个目标显示等待；多个候选停止自动绑定，不猜账号。

## 模块与数据流

```text
Win32 窗口事件/低频校准 → 只含几何的本机管道 → 桌面窗口状态机
                                                       ↓
选定单会话 + 日期/条数 + 主动输入 → 本机预览 → 按次确认 → 一次云请求
                                                       ↓
                                            回复候选 / 话题 → 用户复制
```

- `desktop/copilot/`：Electron 壳、受限 preload、纯几何策略、生命周期控制。只加载精确本机副驾页；禁止远程导航、子窗口、任意 shell/文件/网络 IPC；renderer 保持 sandbox/contextIsolation/nodeIntegration=false。
- `scripts/copilot_window_watch.py`：只读 Win32 几何监测。消息不含标题、账号、正文、路径；EOF/退出释放 hook。管道故障时主窗口隐藏，不能保留陈旧的绑定状态。
- `dashboard/copilot/`：最近记录选择、独立回复契约、预览和一次消费。不复用长报告/时间线输出契约。
- `dashboard/static/copilot/`：独立页面壳，复用本机 Cookie、Host、Origin、CSP，不依赖主站 shell DOM。
- `copilot` 是默认关闭的可选模块。新增字段 `Module.default_enabled`，旧模块默认行为不变。真实生成还要求 `analysis` 开启。

服务商固定 endpoint、DPAPI 配置、禁代理、拒绝重定向、响应上限、失败不重试保持不变。提取 JSON transport 与报告校验分离，不改变旧分析的返回契约。

## 窗口状态机

`waiting → bound-visible ↔ bound-hidden → waiting`，额外状态 `ambiguous / paused / error`。

- 初次启动不自动连接聊天内容。几何只绑定唯一可识别微信顶层主窗口；窗口失效或 PID 改变立即解除，不按复用 HWND 延续旧身份。
- 默认右侧 8 DIP 间距；空间不足尝试左侧；两侧均不足只显示边缘小胶囊，不覆盖微信输入区。用户主动展开可显示有限重叠面板，默认不主动展开。
- 使用显示器工作区而非整屏，避开任务栏；物理屏幕坐标由 Electron `screenToDipRect` 转换，不能简单除缩放比例。
- 状态没变化不重复 setBounds；事件合并，移动期间限速，静止时低频校准。目标消失、桥失联、锁屏/不可见时 fail closed 隐藏。
- `showInactive`，不调用 focus/SetForegroundWindow。用户主动点击的输入不算被动抢焦点。
- 关闭只退出副驾和自有子进程，不关闭微信、既有控制台或同步任务。暂停停止后续监测/建议准入，恢复不补发云请求。

## 建议流程与隐私

1. 用户在本机选一个可见归档会话，选择日期、最多 80 条历史文字（硬上限 200），可主动输入最新文字（硬上限 4,000 字）。默认不含语音转写。
2. 按选择范围取最近记录，保留时间顺序；先锁会话再筛选，不搜索其他会话。总上下文硬上限 20,000 字，超限截取需显示实际覆盖。
3. 预览显示接收方/模型、会话范围、历史/手动文字计数、最多一次调用以及脱敏局限；不返回历史聊天原话。
4. 一次确认消费短期 preview，执行前复验模块、会话可见性、源签名、模型配置、提示版本及 binding revision。双击不会重复请求。
5. 结果只含三类回复、延续话题和边界提示，不能生成好感百分比/心理诊断。所有输出按文字渲染；不执行模型 HTML、链接或指令。
6. 切换对象、范围、方向、新文字、原生窗口身份后清空预览/旧结果并递增 revision。已在途请求不宣称已撤回，晚到结果不能显示给另一对象。
7. 失败/超时/断连不自动重试；明确可能已计费。重新生成必须重新预览确认。记录错误只用固定安全码，不包含正文、模型原始响应或密钥。

## 视觉规范

延续获批的柔和绿白界面：正文 `#243c3b`，强调 `#247361`，辅助 `#66796e`，背景 `#f7f8f5`，表面 `#ffffff`，分隔 `#e2e9e3`。系统中文无衬线作为正文和标题；数字使用系统等宽变体，无字体下载。

唯一突出的视觉元素是贴边的小胶囊：显示绑定/暂停/有新建议状态，而非动画闪烁。展开仅短距离淡入，尊重 reduced-motion。按钮至少 32px 命中区，键盘焦点可见，设置/输入面板可滚动。紧凑状态只保留一个建议和复制动作；历史范围与费用确认展开可达，不默认勾选。

## 验证与发布门槛

- 单元：左右吸附、极小工作区、负坐标、缩放转换边界、最小化/恢复、前台切换、迟到事件、暂停、桥失联。
- Python 合成：默认关闭、无确认无网络、最多一次、换人/源变/配置变失效、回收站阻止、错误不泄露、报告 transport 回归。
- 浏览器合成：键盘/缩小/长内容、切人清空、结果乱序、无内联脚本和远程资源、无自动云请求。
- 原生合成：只对应用自己创建的目标窗口执行移动/缩放/最小化测试，验证副驾 bounds/visibility/focus；不把这些测试冒充全部微信版本实测。
- 微信实机只读诊断可核对唯一窗口绑定和几何状态，不读取标题正文、不控制微信。无法实测的移动/多屏/版本兼容必须留在验收记录，不能发布为已验证。
- 完整回归、公开扫描、独立 review/debug、当前提交 CI 后才可标 `1.0.0` 正式版；此前标候选。不得将本机私有数据、截图、运行路径或凭据纳入公开提交。
