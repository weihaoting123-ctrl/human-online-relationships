# 离线导入的保存与复用

此契约从 v0.1.2 开始覆盖网页导入，以及 `convert_markdown.py`、`convert_weflow.py`、`convert_weflow_cli.py`、`convert_ciphertalk.py` 的联系人包输出。实际发布状态以对应 Release 为准。

## 三种结果

| 输入与已有档案 | 保存行为 |
| --- | --- |
| 同一转换材料、来源身份和选项，已有文件完整 | 复用同一包，不改消息、表情或已有报告的内容和修改时间 |
| 内容、明确联系人、账号或影响转换的选项不同 | 新建包；不覆盖旧包，也不按显示名自动合并 |
| 旧包没有新版清单，或材料损坏、缺失、被修改 | 保留旧包，另建完整新包；不自动修补旧资料 |

离线 CLI 的成功 JSON 保留原有路径和数量字段，另提供 `created` 和 `reused` 布尔值。输入文件改名或移动不影响复用；输出根不同则分别保存。指纹依据转换后的材料，不承诺区分所有原始文件字节变化。

这不是消息去重器。同一时间相同内容、不同消息 ID，乃至输入中完全相同的重复记录，仍按原有转换结果保留。增量合并是另一个明确入口，不能将重复导入与删除重复消息混为一谈。

## 身份与完整性

联系人显示名不是唯一身份。保存指纹包含明确联系人标识、可取得的账号身份、实际格式和转换选项，并区分请求值与来源原值。来源没有提供的身份仍为未知，不靠猜测补全。

离线包使用 `import_manifest.json`，网页使用独立版本的 `dashboard_manifest.json`。复用时核对预期文件集合、文件摘要与实际转换材料。WeFlow 离线导入的 `messages.json` 与 `emojis.json` 一起发布；表情清单不是表情图片已下载的证明。

网页 v1 清单缺少完整身份上下文，不自动推断升级。旧网页包可继续读取，升级后的首次重新导入可能产生一个新包；以后同一新版输入才核验复用。网页与离线 CLI 有不同原件/统计流程，不保证跨入口复用同一个包。

## 并发与中断

共同根锁让本版本的网页与四个离线 CLI 协作串行保存。网页同进程请求保留线程串行；另一个进程持锁时返回固定忙碌错误，不自动重试。

新材料暂存在联系人目录之外的固定本机私有工作区域，完成后才发布为正式目录。失败只清理本次暂存物；发布成功后，即使响应失败，也不删除已提交包。结果不确定时先检查本地目录，再决定重试；不要通过清空目录处理失败。

遗留暂存物不会被当成正式包，也不自动删除未知目录。拒绝符号链接和 Windows reparse 重定向。此保护针对遵循共同锁的入口，不能阻止其他程序或尚未接入的旧提取器同时改动资料。

文件 flush/fsync、支持平台的目录同步和进程退出测试不等于整机断电或磁盘损坏恢复保证。独立备份仍有必要；同盘副本不能防磁盘整体损坏。

## 本轮未改变

- `contact_bundle.resolve_bundle_paths`、已有包 ID、管理数据库和显式 `merge_into_bundle`。
- 原生微信同步的检查点与备份流程，以及旧微信/QQ 在线兼容提取器和显式输出文件模式。
- 不自动迁移、重写或清理旧包，不上传材料，不运行云端分析，不注册计划任务。
- 不包含导入预检向导，也不代表 DATA-01、IMP-01 或跨平台原生采集已全部完成。
