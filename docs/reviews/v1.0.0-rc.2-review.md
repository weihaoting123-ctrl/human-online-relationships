# 1.0.0-rc.2 candidate review · COPILOT-02

Scope: [#46](https://github.com/weihaoting123-ctrl/human-online-relationships/issues/46),
[design](../superpowers/specs/2026-09-24-copilot-auto-context-design.md),
[usage and limitations](../copilot.md). This stacks on RC1 / #45 and is not a

## Design and privacy review

The inspected WeChat 4.1.13 accessibility tree exposed outer rendering panes,
not a supported conversation-title element. No accessibility injection, memory
write, hook, restart, hidden flag or database-recency inference is used. A bounded
header region must be explicitly calibrated before the first capture. The
temporary Ctrl+Alt+F8 shortcut is registered only during the two-point calibration
and unregistered on completion, cancellation, timeout, pause and shutdown.

The isolated Windows PowerShell worker uses a fixed C# read-only capture helper
and built-in Windows OCR. Only the calibrated small bitmap enters volatile memory;
it is disposed after recognition. Window process/version/geometry/visibility,
foreground and occlusion checks fail closed. Neither a full-screen bitmap nor a
screenshot/title file is created. The only persisted preference is bounded numeric
region coordinates and a fixed version-profile identifier in private runtime data.
The main process owns worker lifetime, request size and timeout. The renderer
cannot submit an HWND, filename, executable or arbitrary crop.

OCR is not identity. Glyph errors, CJK-space joining, an unarchived same-name
contact or a stale archive can produce a wrong unique candidate. Exact archive
name lookup never verifies the account. Every automatic preview requires a new,
unchecked identity confirmation before a separately confirmed model request.
Raw observed titles are not appended to prompts or saved as report/log fields.

The resolver reads the indexed metadata only, includes hidden/missing/cross-source
duplicates when deciding ambiguity, and ignores management aliases as identity.
The ten-second token freezes source metadata and the observation generation.
Revocation and send claiming share one lock; provider I/O stays outside it.
Automatic preview and run both request a genuinely new native sample. Browser
mode remains manual. No real chat body, audio, key, cloud request or WeChat input
was used in these tests.

## Independent review and regression findings

The native implementation and backend/UI were reviewed by different agents.
Findings drove synthetic regressions for delayed index reads crossing TTL,
same-window A-B-A transitions, native-target changes replaying cached titles,
queued heartbeat coalescing, and expired cached observations returning after a
status refresh or late binding response. Observation age now uses local monotonic
receipt time, not the native frame or HTTP-response time. Invalid Unicode format
controls are rejected at the native observer as well as the backend/UI boundary.
Final reviewed changes have no known blocking finding; this is AI-assisted review,
not an external security certification.

## Scoped deployment verification

Before restart, safe aggregate status showed no active analysis or backup and the
copilot module remained off; no existing native assistant process needed closing.
Eighteen allowlisted runtime/document files were copied after source-only rollback
and baseline-identity checks. The existing dashboard app had unrelated changes,
so only the six binding-route lines were patched; it was not overwritten.
Only the verified project dashboard was restarted. WeChat was not restarted,
focused, moved or modified. Existing chat records, keys, backups and sync tasks
were not migrated or overwritten.

Forty-five synthetic backend/API tests pass with imports pinned to the deployed
runtime. The assistant HTML and JavaScript return HTTP 200 with the new controls;
one native assistant parent process is running. The final reconnect fix refreshed
only the allowlisted JavaScript and restarted the assistant itself while its module
was still off. The module remains off and the
first header calibration is still required. This is deployment/startup evidence,
not a claim that a real title was captured, identified or analyzed.

## Remaining gates

First calibration and real-header recognition require the user's visible title
region. No real title was read or screenshot captured during implementation.
Other WeChat versions, mixed-DPI displays, lock-screen/virtual-desktop recovery
and real model quality/cost remain unverified. There is no live message-body
capture, stable peer/account ID, automated sending or real-time city-activity feed.
Existing archives, backups, credentials and sync schedules are outside this change.
