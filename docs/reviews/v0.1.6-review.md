状态：候选，尚未正式发布。追踪 [UI-04 / #32](https://github.com/weihaoting123-ctrl/human-online-relationships/issues/32)，设计与边界见 [计划](../plans/2026-09-15-density-calendar.md)。本记录只含源码和合成验证说明。

## 实现与审查

单职责 DensityCalendar 接收无正文 DTO，无网络、存储或 AI 行为；时间线仅委托渲染。后端在原有效消息循环添加日计数，周/阶段/节点算法不变。稀疏日列表不截断，覆盖边界限于统计时点和支持年份。完整仅指本机聚合，不保证微信历史齐全。

默认最新有效记录月份，月/年切换、年份与前后翻页、十二个月下钻；分档使用全选定范围日峰值，切月不改变标尺。文字条数、稳定读数区、方向键、触摸、浅深色及减少动态效果共同保证可读性。旧报告缺失或异常 DTO 明确降级，未来/范围外不当作零。

后端独立规格和质量审查通过；额外差分验证 75 组合成用例原结构化字段保持一致，36,890 个支持日期可完整返回。前端规格审查发现非字符串 as_of 可抛异常及年缩略零背景覆盖未来样式，均新增合成测试后修复。桌面月历、全年、手机深色合成截图已检查；未查看私人聊天截图。

## 测试证据

- TDD：后端先验证缺少每日字段失败，再通过 27 项；额外 metrics/API/mock-AI 42 项通过。
- 独立日历 8 项、详情/预览/报告及原时间线 UI 22 项通过；包括旧报告不重查、不自动分析。
- Node 目录检索排序 8 项，全部前端 JS 语法和 diff 检查通过。
- 完整合成回归：738 项、302.268 秒、0 失败，9 项既有 Windows 合成符号链接权限跳过。最终小屏字号和语义元素修正后另跑日历 8/8 与时间线 22/22 定向回归（分别 4.425 / 41.694 秒），不是用较早完整运行冒充逐字冻结源码的重跑。

最终质量审查还发现年份选择器 13px 样式盖过手机主题规则；先补失败断言再改为 16px，避免小屏聚焦缩放。月份按钮内的缩略网格改用符合 phrasing-content 语义的 span。独立复核通过，无剩余待修项。公开扫描和远端树核验作为提交/上传门槛执行。

## 部署和限制

仅发布审核的公开源码、文档和虚构测试，私人部署不上传 Git 或数据。定向升级日统计函数、日历资源、时间线委托及 HTML 资源引用；保留其他本机版本差异、模型和任务配置。源码回退不涉及聊天删除。后端激活需确认空闲后重启；不触发分析、导入、同步、备份或转写。

不是屏幕阅读器人工认证，也未验证真实模型输出、任意微信版本采集或原媒体完整性。旧报告不能恢复当时未保存的逐日快照。候选依赖前序分支，未以本机测试冒充远端 CI/正式 Release。
