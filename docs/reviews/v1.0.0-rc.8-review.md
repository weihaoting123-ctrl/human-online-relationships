# 1.0.0-rc.8 candidate review · COPILOT-06

Refs [Issue #50](https://github.com/weihaoting123-ctrl/human-online-relationships/issues/50)
and the [reading plan](../plans/2026-09-27-copilot-reading.md).
This candidate prioritizes timely, unobtrusive text reading. Optional insight
cards are deferred and are not part of this release tree.

## Implementation and review

- One private pipe worker per fixed grant reuses imported reader code and
  verified shard copies. Every round still verifies source bytes (including
  WAL/SHM); unchanged rounds skip copies, SQL and decoding. Changed shards
  replace only their own copies. Refresh failure never reports a stale copy as
  current. This is not a push subscription or a zero-disk-I/O idle loop.
- Worker input is bounded, source-pinned and single-flight. EOF, idle timeout
  (30 seconds) and grant lifetime (900 seconds) release its own temporary copies.
  Parent failure closes the worker; the next cursor cannot silently start a
  replacement. Forced termination may leave private temporary files.
- Model work uses one bounded thread per grant. Reader ticks continue during
  a paid request; context revisions discard obsolete replies. Queued obsolete
  work uses no call attempt. Binding validation and actual paid-call claims
  share the binding lock, so an intervening title revocation wins before claim.
- Browser polling waits two seconds after each completed tick and keeps phase
  text stable. Stop/switch/expiry fence late responses, with no focus theft,
  automatic expansion, sending, source switching or restored consent.
- Existing exhausted-session semantics remain: the last successful result can
  remain with an explicit stale warning; an outgoing message clears it. No
  seventh attempt is possible. Actual in-flight requests may still be billed.
- Full regression exposed an existing browser timer overflow: far-future
  preview expiry could immediately hide the confirmation panel. The delay is
  now bounded to ten minutes; backend expiry and explicit consent remain
  authoritative. The synthetic regression uses an invented distant timestamp.

Implementation and separate review passes were performed by one agent, not an
independent human auditor. Review covered locks, lifetime, stale-result races,
identity checks, original-data ownership, pipe validation and publication scope.

## Evidence

- Reader/service/transport targeted regression: **70 tests pass / 34.385 s**.
  Includes a real local Python private-pipe process returning synthetic data;
  no source account or model is contacted.
- Exact staged-tree desktop Node and catalog: **81/81 pass / 0.796 s**.
- JavaScript syntax and staged whitespace checks pass. Index/working-source and
  clean staged-tree publication guards pass.
- Full clean-tree Python/browser regression, deployment hashes and remote CI
  are recorded on the associated PR. Interrupted or failing earlier runs are
  not counted as passing. Initial integration had isolated archive-availability
  and loopback-resource failures; neither assertion is suppressed. The exact
  release-tree regression is required before deployment, with synthetic-only
  diagnostics retained locally if an intermittent failure recurs.

## Acceptance boundaries

No real chat, title, screenshot, key, account identity, media, backup, private
runtime log or configuration enters this release. No real cloud request or
live-chat grant was made during implementation or testing. Original source
databases, export schedules and backups are unchanged.

Copies/query counts are synthetic evidence, not real database latency. Byte
hashing, WeChat disk flush and model latency remain significant; two seconds
is a polling delay, not a response guarantee. Cross-version/native identity,
mixed-DPI, lock-screen recovery and real model quality/cost acceptance remain
open. Current-commit CI is required for merging, and this remains a candidate,
not formal 1.0 or a security certification.
