# 1.0.0-rc.6 candidate review · COPILOT-02

See [bounded fix plan](../plans/2026-09-24-title-calibration-rc6.md).
This is not formal 1.0 acceptance or proof of end-to-end live chat binding.

## Root causes and safeguards

The fixed outer-window probe overlapped top chrome and could cut off the title's
left edge. Small CJK glyphs could yield no OCR line at desktop DPI. OCR glyph
bounds could also omit antialias edge pixels. Pure synthetic geometry/bitmaps
reproduce these cases without capturing a real window.

The probe now stays within the standard title header; only bounded in-memory
pixels are enlarged and all OCR bounds are converted back to original pixels.
Horizontal one-DIP glyph fringe is permitted, but blank edges remain required.
Regression testing found a further risk: enlarged OCR can omit visible ellipsis
ink. Both calibration and ordinary reads now inspect the original bounded strip
outside the glyph box, including distant suffixes. The failing ellipsis fixture
was retained and passes after the guard was added.

No cloud calls, message writes, exports, dependencies, source-identity changes or
consent changes. No actual screenshot, title, account data or runtime material is
included in the public tests. Manual regions are not migrated; a too-tight or
contaminated old region may need explicit recalibration. OCR is not identity proof.

## Verification

- Related Windows native/OCR suite: 19 tests passed, including real local WinRT
  OCR on invented pixels, standard layout, DPI conversion and unknown suffixes.
- Desktop Node and catalog suites: 78 tests passed.
- Independent re-review reran all 19 related tests without skips, checked DPI
  propagation and disposal, and found no remaining blocking issue. An additional
  invented-title calibration/recrop/read check passed at 96 and 192 DPI. Review
  is AI-assisted and is not a security audit or live-source acceptance.
- Full local Python/UI regression: 1,051 tests in 483.595 seconds, no failures,
  nine conditional skips. The 19 Windows header tests themselves had no skips.
- Staged and working-source publication scan passed; final committed-tree scan
  is still a publication gate. Only reviewed source files are deployed, retaining
  rollback copies and leaving runtime settings, archives and schedules unchanged.

## Remaining acceptance

Synthetic tests cannot prove actual WeChat capture or archive identity matching.
Recalibration restarts the owned OCR worker and loads the new source; no WeChat
restart is needed. Other layouts/versions, mixed-DPI behavior and real model
quality retain their existing acceptance gates. No formal release tag is created.
