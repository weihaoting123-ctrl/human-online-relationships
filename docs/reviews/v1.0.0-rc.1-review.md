# 1.0.0-rc.1 candidate review · COPILOT-01

Scope: [#44](https://github.com/weihaoting123-ctrl/human-online-relationships/issues/44),
[design](../superpowers/specs/2026-09-24-copilot-v1-design.md),
[usage and limitations](../copilot.md). This is a release candidate, not a formal 1.0 release.

## Implementation and review

The optional Windows shell uses a sandboxed, isolated-context renderer at one
fixed loopback page. Narrow validated IPC controls only the assistant. Copy is
write-only, bounded by Unicode code points and requires transient user activation
in preload. Renderer network, redirects, child frames and permissions are denied
outside the reviewed local surface. No shell execution or arbitrary URL/file IPC
is exposed to the page.

An external WinEvent watcher reads geometry and visibility only. It neither
injects into WeChat nor reads titles, accessibility text or process memory. Event
bursts are coalesced at 30 Hz; a 500 ms full-candidate fallback and heartbeat remain.
Ambiguity, stale/broken protocol, desktop changes and minimization fail hidden.
Passive show/position does not focus or alter WeChat. Explicit editing is separate.

Reply assistance is independent of report schemas. Default-off copilot and the
existing analysis switch are both required server-side. Preview selects one
indexed visible conversation, uses recent text within explicit bounds, reports
actual coverage, and stores a one-use in-memory snapshot. Source, configuration,
prompt and admission are checked again. Unknown outcomes are not retried. This
does not claim semantic correctness, total anonymization or real-time capture.

Independent specification and quality reviews found and drove regression fixes
for actual-bound magnetic snapping, free-float coordinates/monitor selection,
fresh observation after pause, no-drag frameless regions, compact/bubble clipping,
pause authorization invalidation, redirect confinement, native copy/Unicode bounds,
analysis admission and avoiding unrelated archive refresh during scoped requests.
The final reviewed code had no remaining blocking findings. AI-assisted review is
not independent security certification.

## Verified locally with synthetic material

- TDD: feature absence and the above edge cases were reproduced before fixes.
- 33 Node tests: positioning, lifecycle, dual-monitor synthetic coordinates,
  protocol, launch destinations, IPC shape, clipboard bounds and activation.
- 28 Python watcher tests: event coalescing, heartbeat/fallback, ambiguity,
  partial registration failure, message pump, parent/EOF and cleanup.
- 18 browser tests: default/off gates, consent, revisions/late responses, literal
  rendering, production CSP, copy routing/failure, keyboard and narrow layouts.
- Real Electron main/preload in an isolated test root: five checks pass for
  sandboxing, no call before confirmation, one synthetic call, clicked copy bridge
  and external network blocking. Watcher is an in-memory fixture; clipboard writes
  are intercepted. No real archive, clipboard change or model call occurs.
- Seven native fixture checks pass: tray bitmap, inactive show, movement/resize,
  minimize, restore without panel activation, other-app hiding and bridge failure.
  Only the two windows created by this fixture are moved or minimized.
- Electron 44.4.5 runtime download verified against the locked package SHA-256;
  npm lock-only audit reports zero vulnerabilities. Runtime/binaries are not in Git.

Whole-repository regression, final publication scan and current remote CI are
tracked separately below as their results become available. Older candidate CI
does not satisfy this release gate.

Final local full regression: **902 tests in 413.106 seconds, exit 0, nine
environment-conditional skips, no failures**. Node desktop 33/33 and catalog 8/8
also pass. Two old chart probes each pass five additional repetitions after
aligning synthetic pointer/keyboard input with settled scroll frames; the
interactive tooltip still receives real pointer events and exact value assertions
remain. The diagnostic UI file separately passes all five tests. No production
chart behavior was changed to satisfy these tests. The screenshots environment
variable is omitted rather than set to the truthy string `0`.

The first full run executed 898 tests in 408.421 seconds, with nine conditional
skips and two failures: a pre-existing backup status completion race and an old
browser assertion that read before its asynchronous report response. These are
not counted as a passing regression and are being fixed with synthetic timing
barriers before the final rerun.

The backup fix rereads status after acquiring the backup lock, so a previously
read `running` snapshot cannot override a newly published terminal state. A short
process-local I/O lock coordinates dashboard reads with atomic replacement.
Independent review found no inverse lock order. The original HTTP scenario and
two deterministic race tests each pass 20 repetitions; 45 backup tests pass with
one conditional symlink skip. Existing issue #30 remains open: a separate Windows
CLI process holding an ordinary read handle can still obstruct replacement
(WinError 5); the process-local lock does not solve that pre-existing cross-process
case. No real backup or restoration was run to test this fix.

## Scoped local deployment

The local dashboard was not listening and no matching dashboard process was
running. Four modified runtime source files have independent source-only rollback
copies; unrelated differences in the existing app were preserved by applying only
the copilot route/import changes. New assistant files and the verified runtime
were copied by an explicit allowlist. Chat archives, media, backups, keys, provider
settings and synchronization schedules were not migrated, deleted or overwritten.

The deployed imports and 21 synthetic backend/API tests pass against the private
runtime source in an isolated fixture directory. The dashboard and assistant page
return HTTP 200; served JavaScript matches the reviewed file. Native processes are
running and a geometry-only aggregate reports one uniquely bound candidate. The
copilot module remains off until explicit activation. This is startup/read-only
binding evidence, not a real WeChat movement or live-model test.

## Remaining release gates

Actual WeChat-version behavior, mixed-DPI monitors, lock-screen/virtual-desktop
recovery and real model quality/cost are not established by these fixtures.
Live contact/message capture, current city activities, other native platforms and
autostart are not implemented. No operation here sends a WeChat message, modifies
source chats, changes sync schedules, automatically confirms cloud calls or
publishes private deployment material.
