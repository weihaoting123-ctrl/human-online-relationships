# 项目托管与默认决策

生效记录：2026-09-07。维护者已委托代理判断项目内原本需要确认的日常事项。本文记录协作方式，不授予第三方账号权限，也不取消系统、安全或平台要求。

当前规范适用于公开源码项目的维护；源码工作不自动授权读取真实归档、运行私人同步/备份、采集凭据或连接微信。私人部署另按具体维护目标、数据边界和可回退条件核验。

## 由代理直接决定

- 需求分诊、优先级、迭代拆分、验收条件及非目标；从既有需求池选择有界工作，不把整池候选一次性标成已确认或已实现。
- 产品流程、UI 细节、模块接口、兼容策略和技术选型。默认复用已有架构，选择容易验证、可回退、维护成本较低的方案；技术方案不再逐项询问。
- 在项目范围内修改源码、补合成测试、独立 review/debug、修复 CI、维护文档、Issue 和里程碑；验证失败时自行定位与修复。
- 验收通过后提交审阅过的公开源码、合并 PR、按实际变更标注版本并发布 GitHub Release。保留旧标签，不用失败或旧提交的 CI 代替当前验收。

需求池中的“范围确认”可由受托代理逐批完成，记录选定 ID、理由和验收条件；未选中的候选保持原状态。需要实机或人工辅助技术的验收仍要有对应实测证据，不能由代理审查代替。

免除日常方案确认不等于免除设计、测试或审查。重要取舍写清依据、影响、回退和待验证事项，结果与风险主动汇报，不让维护者重新完成技术选型。

## 不因托管取消的保护

- 不发送微信/QQ 消息，不修改或删除其原始聊天；不将聊天、媒体、账号资料、密钥、数据库、备份或私人运行历史放进公开仓库。
- 真实云分析继续使用本地工作流的单会话、日期范围、接收方与调用计划确认。代理不替用户勾选发送或重复计费确认，不把笼统托管当作全量外发、无人值守付费调用的授权。
- 无明确可用预算时，不购买、充值、开通收费服务或新增付费调用；未知调用不自动重试。优先使用合成响应和离线验证。
- 多个账号或数据来源身份有歧义时不猜选、不扩大到所有账号。仅跳过该受阻动作，继续能独立安全完成的源码或合成验证工作。
- 不用删除、清空或重建数据库解决迁移失败；不覆盖已有备份。公开发布与私人部署升级分别核验，不因发布就直接替换正在运行的服务或数据。
- 不执行超出已有授权的对外承诺、身份验证或不可逆操作。登录、验证码、确切身份或无法安全推断的数据授权仍缺失时，只请求最少的必要用户操作；其余选择由代理承担。

## 默认推进顺序

1. 数据完整性、权限与错误边界：先处理 DATA-01、SRC-01 的安全保存和兼容入口收敛，以合成材料验收。
2. 能力状态与导入流程：PLAT-01、IMP-01 明确支持、就绪、预检和结果覆盖，不把未安装等同不支持。
3. 工作区与小屏 UI：在稳定契约上推进 UI-01、UI-02、演示与管理效率。
4. 作业状态、媒体/备份覆盖和多平台实机适配按依赖独立迭代，不宣称未实测的平台已支持。

此顺序是默认决策，不是全部需求已开工或发布日期承诺。发现实际阻断、回归或更高风险时可调整，并在相应需求记录原因。

## 每轮完成标准

- 选定目标、稳定需求 ID、边界和验收；仅有范围变化才重新调整计划，不重复要求维护者确认普通方案。
- 先建立可复现的失败用例，再做最小实现；独立检查数据、时序、焦点、授权与错误分支。
- 按改动风险验证，功能变更跑相关及完整合成回归；只改文档时如实记录文档检查，不冒称再次验证应用。远端 CI 作为对应合并的门槛。
- 公开前审阅精确文件、执行发布扫描并核对远端 tree；软件发布核对 VERSION、CHANGELOG、标签与 Release。纯文档维护不虚增软件版本，也不改写已发布版本。
- 远端写入结果未知时，先回读核对资源和提交，再决定后续动作；不盲目重试创建 Issue、标签、Release 或模型请求。
- 汇报本轮成果、证据、遗留事项和下一步；未完成或受阻项目保留真实状态。存在独立安全工作时继续，不因一个受阻动作停掉全部工作。

托管不是已配置的全天候后台服务。本规范本身不创建定时任务、不启动微信采集，也不承诺对话结束后仍在执行；需要定时继续时使用产品支持的自动化并记录实际配置，不能仅口头声称正在后台工作。
