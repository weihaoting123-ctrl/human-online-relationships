# COPILOT-06 · 及时、无感的本机文字读取（优先）

COPILOT-06 / 1.0.0-rc.8 优化固定会话限时辅助的重复读取和模型等待。源码实现、合成验收与实机延迟分别记录；本轮没有使用真实聊天测量延迟。关联 [Issue #50](https://github.com/weihaoting123-ctrl/human-online-relationships/issues/50)。

## 可核实的差别

参考 [WechatVibe/chatui/app.js](https://github.com/tswawa/WechatVibe/blob/main/chatui/app.js)、[snapshot_cache.py](https://github.com/tswawa/WechatVibe/blob/main/bridge/snapshot_cache.py)、[real_backend.py](https://github.com/tswawa/WechatVibe/blob/main/bridge/real_backend.py)，以 2026-09-27 读取的 main 为准；仅作架构比较，没有复制或执行该项目源码：

- 独立聊天客户端在可见时每 4 秒读取选中会话，15 秒更新会话目录；不是每条消息都收到微信推送。
- 复用读取器与账号快照；数据库和 WAL 的时间/大小变化触发后台快照刷新。已有消息快照可先返回旧数据，所以“无感”不等于零延迟或强一致。
- 选中聊天属于它自己的界面，不构成其能可靠识别原生微信当前对话的证据。
- 本轮没有安装或运行第三方代码、扫描微信进程内存、读取真实聊天或获取密钥。

RC7 的 `dashboard/static/copilot/live.js` 每次 tick 完成后等待 5 秒；`read_transport.py` 每轮新建读取子进程，`copilot_live_read.py` 每轮建立临时快照并查询近期文字。同步层的快照会校验和复制源库及 WAL，读取结束清理临时副本，因此下一轮无法直接复用。子进程读取最大 90 秒，属于超时上限而非测量耗时。

RC7 的模型调用与读取在同一个 tick 链路，调用至少间隔 20 秒，入站合并至少 3 秒；调用等待也会推迟下一轮检查。

## RC8 实现

固定单会话私有管道 worker 复用导入模块和分片副本；每轮仍验证源字节，避免 mmap 写入未更新时间戳时漏掉变化。未变化的分片复用已验证副本，整个来源未变化时返回无正文的 unchanged 游标，跳过 SQL 和解码。新分片、WAL 变化、源替换、内容修改会重新核对；刷新失败不返回旧快照冒充最新。

模型单独在一个有界线程中调用，本机 tick 可继续读取。新文字增加上下文版本；旧版本结果丢弃。仅真正准备发起调用时计入尝试次数，成功但过时的调用也不重试。UI 每轮完成后 2 秒检查，阶段文字保持稳定，不在每次检查时闪烁。

停止关闭 worker 输入，当前有界读取结束后退出并清理自己的临时副本；页面失联空闲 30 秒或总时长 900 秒退出。超时仅终止自建 worker；异常终止可能留下私有临时副本，不自动恢复授权。源字节核对仍有磁盘成本，数秒是体验目标，不能从合成复制计数推断实际大库延迟。

## 验收与后续测量

1. 合成夹具验证复制计数、工作进程复用、并发与迟到结果；真实来源的分阶段延迟测量保留为后续验收，仅可记录计数和耗时，不记录正文、账号、路径或密钥。
2. 授权范围内复用有界读取 worker 和私有副本；对数据库/WAL 的变化按分片刷新，无变化不重复复制。先证明账号、分片新增/轮转、WAL checkpoint、更新中断、锁竞争、缓存过期均不会串号或误报最新，再接入生产调用。
3. 将本机新文字检测与云端建议调度分离。云请求期间仍能检测本人的新回复并标记旧建议失效；不得重复调用或把切换后消息混入在途请求。旧快照不得冒充最新、不得据此自动发送新建议。
4. 显示简洁状态：已连接／检测到新文字／正在生成／已暂停；不抢焦点、无声音、无自动展开。目标是数据库写入后数秒内检测，最终延迟以实机分阶段测量为准。
5. 本机读取与云端外发是不同权限。默认不放宽现有 15 分钟/6 次外发授权、20 秒最小调用间隔；无感不能变成永久后台上传。账号变化、多账号、身份不明立即停止，不猜选联系人。

## 不做的事情

不更换微信、不修改原库、不发送消息、不录制聊天窗、不复制整套第三方读取器，不下载本地模型，不调整每日归档/备份任务。优化实时工作区不是扩大历史归档范围，也不是把识别标题当作已认证的联系人 ID。

## 交付门槛

合成测试证明闲置轮次不重复重建、只处理变化分片、无跨会话混读、无源写入、模型等待不阻塞本机状态、重启不恢复云授权。通过 review 后另行版本化、公开扫描、上传 GitHub 和受控部署；真实读取效果与云模型质量分开验证。
