# COPILOT-02 · RC7 有界标题采集修复

沿用 Issue #46 / PR #47，仅修复标题采集、坐标一致性与旧区域兼容处理。
不改变归档匹配、实时文字读取、模型配置或云端授权。

## 根因与决策

窗口 DC 在合成渲染的界面上可能返回纯黑位图；只测试已存在的图片不能覆盖这个失败路径。改为使用桌面 DC，仅将事前已核验的标题矩形复制到同尺寸内存位图，绝不建立整屏或整窗截图。没有扩大搜索范围或读取正文的回退。

`GetWindowRect` 的不可见边框与跟随器使用的 DWM 可视边框不一致。自动、手动校准和采集统一以 DWM 可视物理边框为原点；只对 DIP 偏移与大小应用 DPI，物理原点不再缩放。DWM 失败时拒绝，不回退旧坐标。旧 `wechat-4.1.13` 区域文件不删除、不猜测迁移；新 `wechat-4.1.13-visual-v2` 仅由明确校准保存。

## 保护与验收

- 保留前后身份、唯一窗口、支持版本、可见性、最小化、DPI、前台与遮挡检查。
- 标准布局额外要求外窗与 DWM 顶边一致，防止非标准顶部边框将固定标题条平移到正文；不支持的顶部偏移在采集前后都拒绝。
- 前后输入桌面必须活动；整个标题矩形必须落在单一实际显示器内，不能仅依据虚拟桌面外接矩形跨越空洞。
- DPI 上下文设置失败时停止；桌面 DC 与图形句柄配对释放，异常路径也不得泄漏或交付不完整位图。
- 合成 native 边界提供黑色 window DC 与虚构 desktop 标题，对真实 C# 控制流先红后绿；覆盖坐标、DPI、负原点、状态变化及资源失败。
- 真实 Electron 壳使用隔离合成档案，验证旧文件保留但不采样、明确重新校准后数值保存、候选绑定和原有逐次授权。
- 独立 review、相关测试与完整合成回归。测试中无真实微信、账号、聊天、截图或模型调用。

## 部署与限制

私人部署只替换精确审阅的源码清单，先核对已安装基线并保留回退副本。
主进程配置版本改变后需重新打开助手，不能仅重启 OCR worker；只结束已核验的项目助手，不关闭微信或服务，不恢复任何云授权。归档、备份、密钥和同步任务不变。

实际标题验证只用有界、前台可见的小区域，在内存处理，输出安全计数和布尔状态。运行材料不进入公共仓库。合成结果与单机诊断不替代其他版本、混合 DPI、锁屏恢复和模型质量的完整实机验收；不据此发布正式 1.0。
