# 项目解构与迭代审查

审查日期：2026-09-06。源码基线：`94180d0`，已发布软件版本：`0.1.0`。本文是现状审查与候选边界，不是新功能已交付声明，也不是已经批准的实现规范。

## 结论

项目已有本机归档、独立管理库、搜索、时间线、按次授权分析和备份能力。下一步应把它从“功能集中在同一个控制台”整理为“入口清楚、能力可判断、处理结果可核对”的应用。

推荐渐进拆分：先修复首次导入到查看结果的完整流程，再提取平台能力和导入服务，最后处理持久作业与各操作系统适配。保留现有数据身份、历史文件、加密缓存、模块开关和安全边界，不整体更换技术栈。

三种路线的取舍：

| 路线 | 收益 | 代价 | 建议 |
| --- | --- | --- | --- |
| 渐进拆分、按用户流程逐版交付 | 每版能验证一个完整流程，现有数据与测试可沿用 | 过渡期存在兼容包装层 | 推荐 |
| 只调整视觉主题 | 改动较小、视觉变化快 | 不解决导入结果、能力判定和处理状态问题 | 不作为本轮主线 |
| 同时重写前后端与桌面打包 | 可重新设计全部接口 | 数据迁移、兼容性及回归范围显著扩大 | 当前不选 |

## 审查方法与证据等级

- 对公开代码、维护文档、测试和 GitHub 待办进行只读检查；没有读取私人部署、真实聊天或密钥。
- 静态代码规模：`dashboard/app.py` 1,366 行，`scripts/sync_all_wechat.py` 2,456 行，`dashboard/static/app.js` 793 行。行数只是职责集中信号，不单独构成重构理由。
- UI 定向探测使用已有随机回环端口夹具与完全虚构的响应；它验证前端状态，不证明真实微信提取或云端调用成功。
- 基线完整回归已有[独立记录](release-verification.md)。本次审查没有重新运行完整回归，不能把旧结果算作下一版本验证。
- 未修复的潜在安全问题按 [SECURITY](../SECURITY.md) 保持非公开；公开需求池只描述建设目标，不公开敏感复现细节。

## 必要功能与责任边界

这些是同一进程/项目内的逻辑模块，不是要求部署十二个服务。UI 分区与代码模块不必一一对应。

| 模块 | 用户需要什么 | 拥有的职责与数据 | 应提供的接口 | 不应承担 |
| --- | --- | --- | --- | --- |
| 应用壳 | 知道自己在哪、返回哪里 | 导航、焦点、主题、工作区生命周期 | 注册工作区、导航、共享通知 | 解析聊天、决定云授权 |
| 平台能力 | 知道当前能做什么、缺什么 | 版本、操作系统、能力及就绪状态 | 固定字段能力快照 | 扫描消息、自动安装依赖 |
| 数据源适配 | 导入已有文件或读取授权来源 | 来源格式、账号确认、平台兼容性 | 探测、读取/解析、能力声明 | 直接修改其他模块的存储 |
| 导入与规范化 | 导入前后能核对数量与范围 | 格式校验、日期、发送方、质量计数 | 预检、确认、导入结果 | 悄悄丢弃旧派生记录 |
| 归档写入 | 重复导入不丢数据 | 包身份、版本、合并锁、原子发布 | 新包/明确合并/幂等复用 | 修改微信原库或重排旧身份 |
| 资料库与检索 | 查找、筛选、排序、管理 | 用户字段与独立搜索投影 | 查询、版本化管理修改 | 把原话做成可随意 CRUD 的业务表 |
| 本机统计与时间线 | 看见阶段、记录间隔 | 时间元数据和可解释统计 | 有界统计 DTO | 推断现实断联或动机 |
| 按范围 AI | 整理用户确认的内容 | 预览、授权、调用计划、缓存、独立报告 | 预览/开始/停止/历史 | 定时外发、未知调用自动重试 |
| 媒体与语音 | 保存、回听、搜索转写 | 原件、预览、关联、转写状态 | 资产状态、解码、回填 | 根据月份猜联系人或把首帧称完整原件 |
| 作业与同步 | 看懂进度和未完成原因 | 步骤状态、覆盖、检查点 | 作业快照、可执行下一步 | 将进程退出成功等同全部材料完成 |
| 备份与恢复 | 防误删、可核验恢复 | 内容对象、版本化清单、协作锁 | 快照、核验、新目录恢复 | 镜像删除、覆盖活动库、默认外传 |
| 发布与支持 | 知道正在使用哪个版本 | 版本、迁移、测试证据、需求状态 | VERSION/变更记录/标签/Release | 发布私人日志、示例用真实聊天 |

### 数据流与依赖方向

```text
已授权来源 / 已有本机文件
           |
      数据源适配与预检
           |
   规范化 -> 归档写入 -> 不变身份的会话包 / 原件
                             |            |
                    管理与搜索投影      媒体 / 语音 / 转写
                             |            |
                      本机统计与时间线 <---+
                             |
                    选定范围 + 按次确认
                             |
                      可选 AI 与独立历史

作业层只协调上述已授权本机步骤；不添加定时 AI。
备份层按版本化白名单读取各模块声明的数据；凭据排除。
页面只消费受保护接口与安全状态，不直接选择任意文件系统路径。
```

本机全归档时间统计可以用于详情页，但不因此进入云端请求。模型只能接收当前确认范围允许的文字与范围内统计。

## 当前实现与主要缺口

| 观察 | 证据位置（对应审查基线） | 证据等级 | 对迭代的影响 |
| --- | --- | --- | --- |
| 选择 Markdown 后再选 JSON，来源仍为 Markdown | `dashboard/static/app.js:624`、`:647` | 合成前端复现 | 文件选择/拖放统一状态管理 |
| 导入成功后停留在维护页，详情隐藏 | `dashboard/static/app.js:557`、`:677` | 合成前端复现 | 成功结果必须有明确入口 |
| 零档案同时出现“没有匹配”和“首次导入” | `dashboard/static/app.js:64`、`index.html:55` | 合成前端复现 | 首次使用、无匹配、读取失败分开 |
| 打开详情重绘列表后焦点落到 BODY | `dashboard/static/app.js:18`、`:550`、`:597` | 合成前端复现 | 详情进入与返回焦点纳入验收 |
| 用户导航覆盖历史，而不是增加可返回页面 | `dashboard/static/shell.js:27` | 合成前端复现 | 仅视图 ID 进入历史，私人检索条件不进入 |
| 小屏首条结果需要较长纵向滚动，表格仍需横移 | `app.css:90`、`apple-ui.css:339` | 定向夹具观测，非普遍性能指标 | 折叠高级筛选、评估小屏摘要行 |
| 模块“启用”、环境“安装”和实际“可用”不是同一状态 | `dashboard/modules.py:47`、`dashboard/app.py:606` | 静态 | 独立能力快照，不改变用户开关含义 |
| 初始状态请求同时做导出器子进程检查及资料库读取 | `dashboard/app.py:1082`、`:606` | 静态；未测性能基线 | 让目录加载与环境诊断独立失败/刷新 |
| 规范化已有无效记录计数，但网页导入缺少核对步骤 | `scripts/message_normalizer.py:61`、`dashboard/app.py:747` | 静态 | 预检显示接受/拒绝数量，不回显错误原文 |
| 15 秒状态轮询可以重叠，尚未验证乱序场景 | `dashboard/static/app.js:775` | 待时序测试 | 独立轮询服务、在途互斥、旧响应丢弃 |
| 作业聚合依据退出码，阶段覆盖状态需要单独表达 | `scripts/run_local_pipeline.py:59` | 静态 | 区分完成、等待、剩余队列、部分覆盖 |
| 每次管理快照刷新源摘要，搜索时也刷新索引 | `dashboard/library_service.py:17`、`dashboard/search.py:204` | 静态；未确认性能瓶颈 | 先测量，后加可重建投影，不迁移管理数据 |
| 多个组件直接引用其他模块私有辅助函数 | `scripts/transcribe_wechat_voice.py:26`、`dashboard/app.py:505` | 静态 | 提取正式服务接口，不只移动文件 |
| VERSION 未作为应用状态统一输出 | `dashboard/app.py:975`、`:1082`、`../VERSION` | 静态 | 发布版本、HTTP 产品标识和 UI 版本统一来源 |

定向 UI 夹具中：390px 视口的表格容器约 341px、表格约 730px，首行距页面顶约 1,277px；320px 对应约 279px、730px、1,460px。这些数值只用于识别该夹具的信息密度，不作为所有设备上的测量结论或固定验收阈值。

### 保留而不是重做的部分

1. 管理数据库已经存在，具有独立字段所有权、乐观版本检查、软隐藏、迁移校验和审计；不要再建设一套联系人数据库。
2. 增量是变更分片完整校对，能处理迟到历史和旧行变化。不能以最后一条消息时间作为唯一游标替代当前算法。
3. 原件保存与预览分离、转写结果缓存、消息回填前保留历史、备份恢复到新目录，应继续作为契约。
4. Apple 风格主题已经有系统字体、浅深色、触摸区域和减少动态效果支持。下一轮重点是信息结构与可达性，不再次堆叠整套覆盖样式。
5. AI 逐次授权、部分覆盖、不确定调用防重试及旧缓存保留是不可放宽的验收项。

## 多平台：分开讨论操作系统与聊天来源

“支持一种文件格式”“某操作系统 CI 通过”“能够读取该系统微信”是三个不同承诺。

| 能力 | Windows | Linux | macOS |
| --- | --- | --- | --- |
| 已有 JSON/Markdown、搜索、管理和本机时间线 | 有实现及合成验证 | 有合成 CI 覆盖；初次运行文档不完整 | 尚无 CI/实机验证，不宣称支持 |
| 当前微信本机读取与初始化 | Windows 专用实现，仍受微信版本/账号状态限制 | 当前无可用适配器 | 当前无可用适配器 |
| 当前云配置与密封缓存 | 使用 Windows DPAPI | 安全存储明确拒绝 | 安全存储明确拒绝 |
| 固定语音运行时安装 | Windows/Python 3.12/AMD64 路径 | 安装器不支持 | 安装器不支持 |
| 已归档材料的备份及隔离恢复 | 合成验证 | 合成 CI 覆盖 | 未验证 |
| 前台 Python 服务入口 | 有入口；Windows 另有生命周期包装器 | 核心入口可用于离线逻辑，需独立安装验收 | 需增加验证，不能从 Python 可移植性推定 |

依据：`requirements.txt:3`、`dashboard/analysis.py:81`、`scripts/bootstrap_voice_runtime.py:228`、`.github/workflows/tests.yml:35`、`scripts/run_dashboard.py`。

| 聊天来源 | 当前定位 | 后续必要工作 |
| --- | --- | --- |
| Windows 微信本机 | 只读采集、稳定副本、账号隔离和变更分片校对 | 明确能力/兼容性、完成多账号确认流程、步骤覆盖 |
| 统一 JSON / Markdown | 跨来源离线入口 | 导入预检、发送方/时间范围质量、统一保存契约 |
| 已有 WeFlow / CipherTalk JSON | 历史格式转换兼容 | 转换器契约测试；不恢复已停用的自动安装路径 |
| QQ / QCE | 保留兼容代码，不等同新控制台完整支持 | 独立安全评审与接口契约，批准前不接入统一自动作业 |
| 其他聊天平台 | 当前没有已验证适配器 | 先确认合法数据来源与格式，再实现最小适配器 |

不把“多平台适配”解释为云端部署、手机读取、跨联系人身份合并或同时读取所有账号。这些都不属于当前范围。

## 迭代边界与版本建议

详细需求、优先级、依赖和验收见 [需求池](../BACKLOG.md)。以下版本是候选，不改写既有里程碑或标签：

- `v0.1.1`：首次导入与导航的有界修复，不迁移数据库、不增加真实提取、后台安装或云调用。
- `v0.2.0`：平台能力、导入预检与工作区结构；结合既有演示/诊断/管理/无障碍待办拆成独立 PR，范围批准后才调整里程碑。
- `v0.3.0`：统一作业结果、账号确认、媒体覆盖和有证据的性能改进。
- `v0.4.0`：按能力分批完成 macOS/Linux 安装、凭据和语音适配；没有验收的系统继续标记未支持。

不能以版本日期到达代替验收。潜在数据保护/安全问题是后续功能交付前的独立门槛；不能因 UI 优先级将其视作已解决。

## 每个正式版本的完成定义

1. 对应需求已获确认，验收标准、非目标与兼容范围明确；只完成文档不算完成代码。
2. 相关合成失败用例先建立，再验证修复；合并前运行必要全套回归，真实调用和人工无障碍验证另行标注。
3. 隐私检查覆盖新增文件、Git 暂存与工作区；独立发布树再检查，不发布运行数据或旧私人历史。
4. VERSION、CHANGELOG、Git 标签与 Release 必须一致；已经提供的版本展示也应一致。统一的页面/状态版本展示由 REL-01 单独实现和验收，不将其误记为 v0.1.1 的既有能力。应用 schema 与缓存版本保持各自独立，不能跟着产品号任意重置。
5. 公开 PR 记录测试平台、通过/失败/跳过、已知限制、升级与回退方式。不可修改已发布标签冒充修复。
6. GitHub 源码发布与私人部署升级是两次不同验收。部署前确认无在途分析/备份，只更新已核对源码，不覆盖私人资料、历史或凭据。

目前只有审查和需求拆分完成。软件版本仍为 `0.1.0`；首轮实现设计需确认后进入详细计划。
