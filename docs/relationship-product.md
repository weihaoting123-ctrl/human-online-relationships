# 人类线上关系可视化

## 项目思路

这是一个以本机聊天档案为基础的关系回顾工具，适用于朋友、家人、同事、合作对象与亲密关系。核心问题从“对方到底是什么人”转为“这段线上交流经历了什么、何时发生变化、哪些计划有后续证据”。不通过消息量判断感情深浅，不诊断人格，不替用户猜测他人的内心。

公开源码使用 `human-online-relationships` 仓库名，内部保留 `she-love-me` 技能标识以兼容工具入口。已有私人运行实例的目录、自动化、备份、数据包身份和凭据不因产品更名而迁移；显示名称改为「人类线上关系可视化」。旧报告与原始导出不重写。

## 三层内容

| 层 | 回答的问题 | 依据与边界 |
| --- | --- | --- |
| 本机记录 | 何时有消息、何时频繁、间隔多久 | 全量时间戳统计；不需要云端模型；归档缺口不等于现实断联 |
| 事件整理 | 那段时间在讨论什么、计划如何变化 | 仅整理用户按次确认的范围，区分文本提及、推测、证据不足 |
| 关系时间线 | 把阶段、计划和后续串起来 | 用户点开节点查看解释、日期及限制；不展示原话或心理评分 |

“距最近消息多久”从整个当前会话的本机归档计算，不用所选历史区间的最后一天冒充最近联系。仅计算有效且不晚于当前时刻的非系统消息；另外列出双方各自最近发言。历史报告显示统计时点，过时档案明确要求先同步核对。

“为什么没联系”默认无法判断。只有聊天中有具体相关叙述时才展示为“记录中提及”，仍不是对真实原因的验证。推測必须另行标记；仅有消息空白、回复慢或未完成计划不能据此判定动机。

## 事件状态

同一事项可以经历：提出计划 → 推进 → 记录中显示落实 / 明确取消 / 尚无后续证据。

时间到了不代表实现；提到同一地点不等于同一次出行。后续事件必须有可关联的时间依据；不能关联时保持独立。每个节点都显示依据等级。抽样、未完成分段或多级摘要丢失上下文时，时间线只代表已处理材料，不能声称完整覆盖。

## UI 设计方案

延续现有 Apple HIG 风格：页面灰 `#f5f5f7`、正文 `#1d1d1f`、系统蓝 `#0066cc`、明确结果绿 `#236c50`、待核对琥珀 `#805600`；暗色自动复用共享主题 token，不新增字体下载。

标题使用本机系统字体半粗体，正文常规系统字体，时间和数量使用等宽数字。视觉重点是“连续时间线 + 活跃密度”，不是新增一排无法解释的关系评分。

```text
会话详情 / 所选分析范围
  最近消息与统计时点 · 双方最近发言 · 归档局限
  ── 活跃密度：频繁阶段与消息空白 ──
  类型筛选 / 时间排序
  ○ 日期 · 初次记录
  │ 频繁阶段 · 讨论计划（AI 整理，依据等级）
  ○ 日期 · 计划推进 → 关联原计划
  │ 无记录区间 · 明示间隔天数
  ○ 日期 · 后续结果 / 尚无后续证据
  点击节点 → 详情弹窗：说明、日期依据、关联与限制
```

自检：时间轴不伪装成精确等距图，长空白可压缩但必须标时长；事实统计与 AI 叙述不混成相同可信度。只对打开/关闭弹窗及局部状态使用短时淡入、轻微位移，避免循环动画和整页弹跳；减少动态效果时关闭动画。手机、键盘、Escape、焦点恢复与长内容滚动同等支持。

## 运行边界

日常同步仍然只做本机增量归档及备份，不自动运行事件 AI。新增语义输出沿用现有分析调用，不额外安排背景付费请求。旧报告不自动重跑；新的提示词与输出结构会使用新的缓存身份，旧成功缓存及历史报告保留。

开发与验收只用合成数据，不把真实聊天读入开发模型上下文，不发送微信消息、不迁移或删除微信数据。

## 使用入口与当前范围

1. 打开「档案资料库」中的一个会话，即可查看不需要模型的最近记录、周频率、高频阶段和记录间隔。
2. 点击时间节点查看说明；「选择范围分析」只填写该会话与日期，仍需本机预览、核对服务商和按次确认，才会发起 AI 请求。
3. 新生成的 AI 报告可展示事件、进展、关联事项及匿名证据位置；用节点类型筛选、时间排序和每页 25 个节点浏览。部分完成会明确提示，旧报告不会自动补造事件。
4. 原生弹窗支持键盘、Escape、焦点返回和减少动态效果；统计方法默认折叠，重要覆盖警示直接展示。

当前以单个会话（私聊或群聊）为边界，不跨会话合并人员身份，不生成全联系人社交网络。群聊中的「其他参与者」是汇总类别，不冒充某个人。AI 处理用户所选文字及明确勾选的本机语音转写，不把图片或原始音频包含在事件理解能力中。时间线整理的是有数量约束的关键事件，不声称逐条消息都对应一个事件。

## 聊天热度（v0.1.3）

在资料库打开会话后，展开「聊天热度」，即可查看本机月历热度和星期 × 小时消息表。
默认以最新有效归档日期为终点显示 90 天，不将旧归档说成已同步到今天；可输入起止日后点击「查看范围」，或重置默认范围。
单次最多 366 个日历日，超限要求调整而非静默截断。需要浏览更久历史时可分段选择日期，现有关系时间线仍保留。

两张热图、消息数、活跃天数、日均、活跃日期排行采用相同选择范围。颜色分别相对本次日峰值和时段峰值，跨范围不能只比较深浅；每格的数字才是实际消息量。
文字、语音、图片等非系统消息都计数，不要求先转写；不计算实际聊天时长，不将重复正文自动当成重复消息。
星期/小时表在小屏可横向滚动，数字与表头可直接读取；不需要模型服务，也不会自动把范围交给 AI。

实现模块为 `dashboard/chat_heatmap.py` 和 `dashboard/static/chat-heatmap.js/css`，只读接口为 `POST /api/activity/heatmap`。
原始时间按本机时区归类，未来/无效/系统消息排除；空白仅代表该份本机归档中没有有效记录。

## 验收边界

合成测试覆盖全归档最近记录、时间窗口、计划与结果关联、部分分析、旧提示预览拒绝、旧报告不改盘、弹窗/键盘/缩放、小屏、深色与 XSS。模型传输与分段流程使用 mock，不用真实聊天运行付费模型。测试结果以对应公开提交的 CI 为准，不公开私人运行实例的验收日志或操作记录。
