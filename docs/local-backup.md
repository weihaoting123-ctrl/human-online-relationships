# 微信聊天本地备份

将项目放在空间充足的非 C 盘目录，备份固定保存在项目内的 `backups\wechat`。控制台“同步与备份”可查看备份状态、最近成功时间、文件分类数量和历史快照，并手动执行备份或校验。

备份保存的是项目已经归档到本机的内容。它不修改或删除微信里的记录，不发送微信消息，也不上传聊天、图片或音频。微信解密密钥缓存、服务商 API Key、凭据文件及临时文件不属于备份内容。

## 保存范围

新建 v2 快照仅从下面七个项目内目录读取允许的文件；不会扫描整个 D 盘或微信安装目录。既有 v1 快照保留原六目录白名单、原始清单与校验值，仍可核验和恢复。

| 来源目录 | 内容 |
| --- | --- |
| `data/contacts` | 联系人聊天包、消息文字、统计及包内派生文件 |
| `data/raw` | 原始导入及本机导出文件，包含 `data/raw/wechat-sync` 中的原始快照 |
| `data/private/wechat-archive` | 已归档的本机附件、来源记录和附件目录索引 |
| `data/private/wechat-voice` | 已归档录音、语音目录索引和本机转写 |
| `data/exports/wechat-media` | 本机图片预览与相册 |
| `data/exports/wechat-voice` | 本机语音及转写展示文件 |
| `data/private/library` | 人工标签、备注、别名、置顶、回收站与模块设置的管理数据库 |

上述目录中的已知密钥、凭据、临时文件、锁文件和目录链接仍会排除。备份不会沿着链接跳到其他目录。文件分类数量按文件统计，不能当作消息条数：一个聊天包可以在一个文件中包含很多条消息，同一录音也可能关联多条记录。

文件以独立的内容副本保存，并按内容去重；不是指向原件的快捷方式或硬链接。未变化的内容可以复用已有备份对象，变化后的内容另行保存，历史快照保留对应的旧版本。源文件后来被删除，也不会因此清理旧快照。全部内容未变化时，成功检查不一定新增一份快照。

## 每日同步与手动操作

使用者可另行配置定时任务运行 `export_all_local.ps1`，克隆仓库不会自动注册任务。入口通过 `run_local_pipeline.py` 依次完成消息同步、附件与语音归档、本机转写和分类，刷新管理投影，再备份当时已经归档的本机内容。各可选模块在设置中关闭后，入口跳过对应新步骤，不删除旧数据；备份核验仍可手动执行。电脑与所选任务运行器需要保持运行；休眠或关机时不能保证准点执行。定时任务不会运行云端 AI 分析。

控制台中的“立即备份”只备份当前本机归档；需要先补齐微信新增内容时，应先完成同步。备份运行期间按钮会禁用，页面仅查询本机进度。新快照全部完成后才加入历史；本轮失败不会覆盖已成功的历史快照。

“校验备份”读取最新快照的备份对象并核对文件内容，不重新读取微信、不新建备份，也不改变原始聊天。日常增量检查会跳过未变化文件，因此不能代替完整的内容校验。命令行若使用 `--max-objects` 仅检查部分对象，页面会显示“局部校验完成”；只有整个快照均已检查才显示“校验完成”。

需要从命令行操作时，在 PowerShell 中先进入当前项目：

```powershell
# 先进入自己克隆的项目根目录。

# 备份当前已经归档到本机的内容
.\.venv\Scripts\python.exe -X utf8 scripts\backup_wechat_local.py --backup

# 读取聚合状态
.\.venv\Scripts\python.exe -X utf8 scripts\backup_wechat_local.py --status

# 完整校验最新快照
.\.venv\Scripts\python.exe -X utf8 scripts\backup_wechat_local.py --verify
```

页面的“快照文件总量”是快照内文件的逻辑大小之和；同一内容可以被多个文件或快照复用，所以它不等于本次新增磁盘占用。查看“新增或变更副本”的数量与大小，可了解这一轮实际新增的内容对象；这仍不包括少量快照清单等元数据占用。备份历史只显示时间和聚合数量，不显示聊天正文或文件名。

## 恢复到新目录

恢复仅提供命令行入口。`--restore-to NEW_ID` 中的 `NEW_ID` 是新的目录名称，不是任意目标路径。恢复结果固定写入项目内 `backups\restored\NEW_ID`，保留原来的项目相对目录结构；目标已经存在时会拒绝运行。

```powershell
# 在项目根目录运行。

# 将 restore-check-01 换成尚未使用的新名称
.\.venv\Scripts\python.exe -X utf8 scripts\backup_wechat_local.py --restore-to restore-check-01
```

此示例恢复到项目内的 `backups\restored\restore-check-01`。每个恢复文件都经过内容校验，整次恢复成功后才出现最终目录。恢复不会覆盖现有的 `data`、原微信数据库或已有恢复目录，也不会自动把聊天导回微信。默认恢复最新快照；需要指定保留的历史快照时，在命令后追加 `--snapshot-id <快照ID>`。

## 备份的实际边界

只有已经在本机归档的内容才能备份。未下载、已在本机缺失或尚未成功提取的图片和语音，不能靠备份凭空恢复；控制台的语音归档面板会单独显示本机缺失情况。

项目与备份都在同一块磁盘时，独立副本有助于保留误删前或变更前的数据，但不能防护整块磁盘损坏。当前功能不会自动把副本复制到另一块磁盘或云端。备份目录本身含有私密聊天资料，不应提交到 Git 或作为普通项目文件分享。

## 全量分析显示“部分完成”时

全量分析与本地备份是两条独立流程。选择“全量文字”表示计划覆盖所选单一会话、日期范围内的全部可用文字及勾选的本机语音转写；运行中途停止，并不意味着文字条数达到上限。

当前单次计划的安全门槛为 80,000 条文字、480 万字或 200 段。超限会在本机预览阶段明确拒绝并要求缩小日期区间，不会静默截断到 8,000 条；全量文字也不等于上传整个账号的所有图片、原始录音或其他会话。

例如某个合成测试在计划尚未完成时遇到模型格式错误，后续调用会停止。页面应同时展示已完成数、计划总数和停止原因，不能将部分执行误解为条数上限，也不能当作所选全部范围的最终结论。已完成的分段仍保存在本机。

点击“重新核对未完成部分”会恢复这份报告的会话、日期、关注方向、覆盖方式和转写选项，先生成新的本机预览。核对本身不调用云端模型。只有用户重新核对接收方与调用计划、勾选单次授权并明确确认后，才会发起后续调用。

成功分段能否复用，以新的调用计划为准；会话与日期、文字内容、模型配置、关注方向及转写等选项需要保持一致。修改源记录、范围或配置后，可能需要新的调用。此前失败或结果未知的请求不会自动重试，必须额外勾选重试确认，并理解该请求可能已经到达服务商、重新执行可能重复计费。
